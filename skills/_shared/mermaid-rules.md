# Mermaid 画图规则

适用于 paper-reader / book-reader / concept 笔记里的所有 Mermaid 图。核心要求：**每张图都必须实际渲染、看过图片、按问题重排**，不能只凭语法正确就交付。

## 1. 渲染 → 看图 → 重排 闭环（必做）

1. 把每个 ```` ```mermaid ```` 块抽成独立的 `.mmd` 文件，放到 scratchpad 里。
2. 用下面的命令渲染（优先用 `mmdc`；没装就用 npx）：
   ```bash
   npx -y @mermaid-js/mermaid-cli -i x.mmd -o x.png -b white -s 2
   ```
3. **用 Read 打开 PNG，亲眼看渲染结果**，对照 §2 的检查项逐条过一遍。
4. 只要有一项不通过就重排，再渲染、再看，直到全部通过。一般 1–3 轮就够。
5. 通过后把最终版替换回笔记。如果为了排版做了语义上的简化（例如拆节点），要在图下方的解释段落里说明。
6. 汇报时如实写明“已渲染校验”还是“未能渲染”。不要用“语法标准”代替实际渲染。

## 2. 看图检查项

| 检查项 | 不通过的表现 |
|---|---|
| 主流向单一 | 数据从上往下流，却有节点被拉到下方又连回上方，出现“回头线” |
| 无交叉 / 少交叉 | 控制线横穿数据线，或两条长边互相交叉 |
| 分层与逻辑一致 | 同一层级的组件（例如并列的几个 buffer）没有排在同一行或同一列 |
| 宽高比合适 | `LR` 图宽度超过高度的 3 倍左右，在 Obsidian 里要横向滚动或被缩得很小 |
| 边的语义准确 | 箭头指向的对象和实际的控制或数据关系不符（例如控制器的边指向了主存，而不是它驱动的 DMA） |
| 标签可读 | 标签重叠、被截断，或节点文字折行过多 |

## 3. 排版规则

- **选方向**：组件多于 6 个、或存在“读入 → 处理 → 写回”这类闭环时，默认用 `flowchart TB`。只有线性的短链（≤ 5 个节点）才用 `LR`。
- **消除回头线**：
  - 读和写回共用同一个资源（主存、存储、网络）时，把它拆成两个节点，例如 `Main Memory（读）` 放顶部、`Main Memory（写回）` 放底部，并在节点文字或解释段落中注明两者是同一实体。
  - 边的声明方向要和期望的布局方向一致。Mermaid 按边的定义方向分层，`A --> B` 会把 B 排到 A 的下方或右方。
- **分离控制流与数据流**：
  - 数据流用实线 `-->`，控制流或反馈用虚线 `-.->`。
  - 控制器不要对每个被控组件都拉一条边。能合并成一条带标签的边，或指向一个 subgraph，就合并。
- **同层并列**：并列组件放进 `subgraph` 并设 `direction LR`，保证它们排成一行。
- **反馈环**：局部回路（例如部分和回灌）只画在相邻的两层之间，用虚线表示，不要跨越多层。
- **节点与标签**：
  - label 一律用引号包起来，节点 ID 要有语义（例如 `NBin`、`MemR`，不要用 `A1`）。
  - 节点文字不超过 2 行，用 `<br/>` 手动换行。
  - 配色不超过 5 种，默认不上色。
- **原图与 Mermaid 分工**：Mermaid 负责讲清逻辑关系，不必复刻论文原图的空间布局。
